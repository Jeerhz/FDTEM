FDTEM · COMET quality estimation · length bias

Does COMET still work
on longer text?

COMET is trained on single short segments. Two experiments ask what happens past sentence scale — one retrains the metric, one stress-tests its encoder on concatenated blocks.

Experiment A

Retrain COMET

Better encoder, and paragraph-level training data. Does correlation with human quality hold up as text grows?

Experiment B

Block-level xSIM++

Bury one perturbed sentence in a k-sentence block. Can the encoder still tell the clean block from the corrupted one?

The earlier Lp-norm aggregation probe was dropped. · Data & models in ~/scratch · logging to W&B · FLORES+ via openlanguagedata/flores_plus

Motivation

An aligner pulls together; a quality metric must also push apart

Aligners (LaBSE, LASER, E5) are trained to place a sentence and its translation near each other. A quality metric like COMET has a harder job: it must also separate a correct translation from one that is nearly identical but contains an error.

  • The concern: COMET saw only short segments in training. On a paragraph, is a single localised error simply diluted away?
  • Two knobs (Exp A): is it the ageing encoder, or the short-segment data, that limits long-text behaviour?
  • The stress test (Exp B): measure error-sensitivity directly, as a function of block length k.
the two forces
pull together ✓

src ↔ correct translation → close in embedding space

push apart ✗

src ↔ translation-with-one-error → must stay farther than the correct one

Both experiments read on this contrast — the second one measures the push-apart force as text gets longer.

Experiment A · data

Length-balanced paragraph mix from Bio-MQM

Bio-MQM segments carry (system, doc_id, seg_id), so consecutive same-document segments form real paragraphs. We slide a window of k segments over each document, concatenate src / mt / ref, and score the window by its mean per-segment MQM penalty (z-scored + sigmoid, per language pair). At k=1 this is exactly the sentence-level score — all lengths share one scale.

  • Balanced by length: every k contributes the same number of training windows — k=1 kept, so sentence quality isn't sacrificed.
  • Train windows overlap (stride 1 = augmentation); validation windows are non-overlapping and never subsampled.
  • Windows over 480 tokens dropped (512 encoder limit).

Experiment A · evaluation

Does correlation with human quality survive length?

On the held-out paragraph validation set, each model predicts a score for every window. Within each (language pair, k) cell we correlate predictions against the gold MQM score — Kendall τ, Pearson, Spearman.

The headline is Kendall τ vs k, one line per model. A model that generalises to long text degrades less (or improves) as k grows.

Experiment B · overview

xSIM++ on concatenated blocks

Standard xSIM++ perturbs a single sentence. We move it to blocks of k sentences: perturb one sentence, leave the other k−1 intact, and ask whether the encoder can still retrieve the clean block.

the question

As k grows, one error is a smaller fraction of the block. How fast does the encoder's sensitivity to it dilute?

the method in one line

Cross-lingual retrieval: query = source block; find its true translation block in a pool seeded with hard negatives that differ by exactly one perturbed sentence.

Zoo evaluated: COMET, Bio-COMET, raw XLM-R, LaBSE, E5 (and any Exp-A checkpoint). No training — pure evaluation. Cased scripts only (de, es, fr, ru); zh/ja/th excluded.

Experiment B · aggregating FLORES+

From FLORES+ sentences to parallel blocks

FLORES+ rows are in document order with a url column marking articles. We take non-overlapping windows of k consecutive sentences within one article (stride = k, so no two blocks share a sentence), and apply the same row window to every language — blocks stay parallel across en/de/es/fr/ru.

  • We pool the dev + devtest splits → 2,009 sentences per language, 562 articles (2–6 sentences each).
  • Partial windows at an article's tail are discarded — only full k-blocks are kept.
  • Larger k ⇒ fewer blocks (below). k=5 is the practical ceiling on FLORES+ article lengths.

Crucial: hard negatives are built per block, from that block’s own k translations — one sentence perturbed, the other k−1 untouched. They are not perturbations of other blocks. The pool for the whole corpus = all clean target blocks (mutual distractors) + every block’s own hard negatives.
Experiment B · exactly what gets perturbed

One sentence, inside the block, for every block

For a k-block we generate hard negatives by sweeping:

  • each position p = 1…k — perturb sentence p, keep the rest;
  • each category — causality, entity, number;
  • a few variants each (default 2, deduplicated).

So a k=3 German block yields on the order of a dozen hard negatives — one clean block, many near-clones each differing by a single edit in a single sentence.

The other k−1 sentences of a hard negative are byte-identical to the clean block. Only the perturbed sentence differs — that is what makes the negative hard, and harder as k grows.

Experiment B · the three perturbation types

Minimal, meaning-changing edits (xSIM++ §2.2)

causality

antonym swap · negation insert/remove · modal strengthening

…ne s'amélioreraient pas → s'amélioreraient

entity

replace a named-entity span with another from a corpus bank

M. Pittman → M. Phéniciens

number

change a digit / ordinal value

88 → 98 · first → sixth

Self-contained & multilingual. Unlike the paper (English via NLTK / spaCy / WordNet), perturbations here run directly on the translation side with compact per-language lexicons — the cluster sandbox blocks the NLTK download anyway. Entity edits need letter case, so they’re unavailable for zh/ja/th (which is why we run cased languages).

Every edit is deterministic — seeded by (seed, lang, category, sentence, variant) — so the whole pool is reproducible.

Experiment B · how we score it

Retrieval rule & the metrics we read

Embed the query block and every candidate; retrieval picks the candidate of maximum cosine similarity (absolute-margin rule, as in the xSIM++ paper). A block is correct only if that argmax is its own clean target block.

Experiment B · result · H100, 13 min · mean over de·es·fr·ru

COMET aligns blocks perfectly — yet can't feel a buried error

Finding. COMET's encoder retrieves the right block among clean blocks flawlessly, but is fooled by a single perturbed sentence 72% of the time at k=2, 98% at k=5 — and from k=3 it places the corrupted block closer to the source than the clean one more often than not. Dedicated aligners (LaBSE, E5) resist this. Bio-COMET behaves like COMET. (This probes the encoder's cosine geometry, not COMET's full regression head — the pull-together / push-apart contrast.)
